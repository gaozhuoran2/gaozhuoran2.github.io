华为ICT大赛创新赛参赛建议：C++竞赛生队伍怎么选赛道、做什么、怎么分工

发表于2026-11-09|更新于2026-11-09|竞赛
|总字数:2k|阅读时长:6分钟|浏览量:

背景：队伍三人都是高中信息学竞赛出身，有 C++ 基础；我另有一点点强化学习/奖励模型的入门知识（之前在课题组复现过 DPO 基线），两位队友另有一点点硬件知识。目标赛事：第十一届华为ICT大赛 2026-2027 创新赛（报名截止 2026-11-30，初赛 2026 年 12 月线上提交材料，中国总决赛 2027 年 3 月）。

本文结论先行：选赛题1，备选赛题2，放弃赛题3；做一个以奖励模型为核心创新点的 AI 应用；由我负责奖励模型与效果指标，另外两位分别负责后端/云部署和前端/材料。

一、三个赛题，先看清楚各自考什么

赛题1：华为云AI创新应用 赛题2：AgentArts智能体 赛题3：Nexent决策智能体
要做什么 任意场景的 AI 应用，用华为云产品（码道 CodeArts）开发并部署上线 在 AgentArts 低代码平台上构建、编排、部署智能体 面向医疗/金融/制造/政务的知识图谱 + 多模态 + 跨文档多跳推理智能体
初赛评分 创新性 60% + 应用价值 40% 创新性 60% + 应用价值 40% 技术评分 100%（算法创新性占 25%）
赛程 初赛 → 中国总决赛 → 全球总决赛 同左 初赛 → 中国总决赛（无全球赛）
对我们的匹配度 ✅ 编程底子 + 奖励模型都用得上 ⚠️ 编程优势被低代码平台抹平 ❌ 无 NLP/知识图谱积累
一个月做出像样东西的把握 ✅ ✅ ❌ 基本不可能

二、为什么选赛题1（针对我们的真实情况）

  1. 赛题1 的指定开发工具「码道 CodeArts 代码智能体」本身就是 AI 写代码工具，赛题要求里明确要体现「需求理解、代码生成、项目构建、问题修复、部署上线」这条 AI 辅助开发链路。我们缺 Web 和云的经验，但读代码、改代码、调试的能力是信息学竞赛练出来的强项——AI 生成的代码恰恰需要有人看得懂、改得动，这是我们的主场，不是短板。
  2. 两位队友的硬件知识在这三个赛题里都用不上，不要为了”用上硬件”去迁就赛道。
  3. 赛题2 是低代码平台路线：人人零门槛、作品高度同质化，”创新性 60%”最终变成拼平台熟练度和包装，我们的编程优势反而被抹平，是下策。
  4. 赛题3 是研究型赛道：低资源场景下知识图谱本体半自动构建、跨文档多跳推理——没有 NLP 积累的队伍一个月内做不出像样的东西，而且它只有两级赛制、无全球总决赛，性价比最低。
  5. 赛题1 的初赛不要求提交可访问的 Demo 链接，提交的是作品信息收集表 + PPT/设计文件/演示视频，材料导向对”逻辑清楚、会写文档”的竞赛生队伍很友好。

三、做什么项目：把奖励模型当成核心创新点

创新性占初赛 60%，全队唯一的差异化武器就是我那点奖励模型知识。方案主线统一为：

LLM 生成多份候选 → 奖励模型打分 → 择优/重试 → 呈现给用户

三个候选场景（都满足”真需求、可演示、奖励模型是刚需”）：

  1. AI 简历诊所 / 面试陪练（首选）：上传简历或回答面试题，LLM 生成多份修改建议，奖励模型挑出最优反馈。
  2. 客服回复质检助手：奖励模型给客服/售后话术打分——这正是 InstructGPT 偏好数据的起源场景，答辩故事最完整（”偏好学习就诞生在这种场景”）。
  3. 作文批改 / 论文摘要润色：教育场景，数据好找，但容易与往届获奖作品撞车。

效果指标的硬性要求（初赛材料必须”提供可量化的指标”），只用两个：

  • 奖励模型打分与真人（导师/同学）打分的 Spearman 相关系数（几十份样本即可算）；
  • 奖励模型择优后的回答在盲评中的胜率（win rate）。

红线：只做「奖励模型微调 + 推理打分」，不做 PPO 训练策略模型、不做 RL 控制类项目——一个月时间不够，翻车概率极高。

四、三人分工

成员 职责 关键产出
我 奖励模型：偏好数据构造、微调、打分链路、指标设计、答辩技术讲解 奖励模型 v1 + 相关性/胜率报告 + PPT 技术章节
队友A 后端 + 云：Python 主链路、CodeArts 开发、华为云部署、RDS/Redis 可访问的 Demo 页面、部署文档
队友B 前端 + 材料：Demo 页面、演示视频、PPT、作品信息收集表 全套初赛材料

说明：两位队友的硬件知识暂时用不上，但对”云服务器怎么选、Redis 是什么”这类概念上手会比纯小白快；三人都先花三天把 Python 语法过一遍（对竞赛生来说足够快）。

五、最小技术栈

  • 语言：Python（FastAPI 做后端）
  • 前端：先用最省事的方案（Gradio 或静态 HTML + FastAPI），把时间留给模型
  • 大模型调用：华为云 MaaS（用代金券购买）
  • 奖励模型：TRL 的 RewardTrainer + Qwen2.5-0.5B/1.5B 级别小模型；偏好数据用 UltraFeedback 二值化版本或自建几百对「好/差回答」
  • 训练：ModelArts；部署：华为云 ECS + RDS(MySQL) + Redis（官方提供了 Skills 一键部署教程）
  • 必读：官方「创新赛学习空间」的考纲解读——那是评分意图说明书，比任何二手攻略都准

六、30 天倒排（11.09 起，初赛约 12 月中旬交材料）

时间 我 队友A 队友B
11.09–11.15 跑通小奖励模型 v0 注册华为云、装 CodeArts、走一遍官方一键部署教程 Python + FastAPI 上手
11.15–11.23 偏好数据、v1 训练、出相关性指标 LLM 主链路 + 打分闭环 + 页面雏形 Demo 页面原型
11.23–11.30 打分服务接入应用 部署华为云、接 RDS/Redis、页面上线 录演示视频
12.01–12.08 写「创新性/数据集/关键代码/效果指标」章节 复现测试、压指标 PPT + 作品信息收集表
12.08–提交前 全员交叉检查 核对提交清单 材料打磨

本周先做三件事：① 队长立刻完成组队报名（报名截止 11.30，且报名后不能换队员和指导教师）；② 报名过审后马上申请华为云代金券（训练和部署都靠它，早申请早到账）；③ 三人各自完成上面第一周的学习任务。

七、可靠性边界与风险对策

  • 预期目标：初赛出线/拿奖是现实目标；中国总决赛（2027 年 3 月）是天花板，不预设。
  • 云部署踩坑：用官方 Skills 一键部署起步，提前一周开始部署，别压到最后。
  • 奖励模型训练不顺的兜底：先用「强模型当裁判」（LLM-as-judge）保证应用闭环，再迭代奖励模型——先保完整，再求亮点。
  • 材料真实性：组委会会复现，答辩效果与材料不符直接取消资格，所有数字必须真。
  • 赛道互斥：每人只能报一个赛道（实践赛/编程赛/创新赛/挑战赛互斥），定了创新赛就别再动其他赛道。

结尾

一句话总结：以「C++ 竞赛生的调试能力」打底，用「奖励模型」做差异点，在赛题1里交出一个完整、真实、可量化的小应用，先拿下初赛。
