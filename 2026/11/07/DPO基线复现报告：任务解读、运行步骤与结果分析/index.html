1.3 GPT 聊天记录的核心结论

  1. 复现首选 Hugging Face TRL（DPOTrainer 现成可用、改 Loss 容易，代码量最少）；原作者代码（eric-mitchell/direct-preference-optimization）作为公式实现参考；dpo-scratch 用于理解数学；Alignment Handbook 留给后期规模化实验；
  2. 最小可跑实验：TRL + Qwen3-0.6B + UltraFeedback 偏好数据，全参训练（显存不够再上 LoRA）；
  3. 两阶段计划：
    • 第一阶段（我的活）：跑通标准 DPO，固定模型和数据，记录 loss、reward margin、chosen/rejected log-probability、accuracy 等指标；
    • 第二阶段（老师的活）：在 TRL 里自定义 Loss，做 IPO、Conservative DPO、Bayesian DPO / Bayesian Reweighted DPO / Pessimistic Bayesian DPO 等变体。

1.4 一句话总结任务

在老师给的服务器上，用 TRL + Qwen3-0.6B + UltraFeedback 跑通标准 DPO（第一阶段），把训练指标整理成表、如实判断”结果怎么样”，汇报给老师。贝叶斯 Loss 老师自己改。

我的产出 = 一套能在服务器上跑通的脚本 + 一份训练指标整理报告。

二、具体跑什么（实验设计）

全部按聊天记录里 GPT 的方案执行，小规模、验证流程优先：

项目 选择 说明
框架 Hugging Face TRL（DPOTrainer + DPOConfig） 代码量最少、改 Loss 最方便
模型 Qwen/Qwen3-0.6B 0.6B 小模型，单卡即可全参微调
数据 trl-lib/ultrafeedback_binarized，取 train[:1000]，再 8:2 切成 800 训练 / 200 验证 UltraFeedback 二值化偏好数据，字段 prompt/chosen/rejected
关键超参 beta=0.1，lr=1e-6，batch=1，grad_accum=8，max_length=512，1 epoch，bf16，gradient checkpointing 有效 batch=8，1000 条 ≈ 94 个更新步，几分钟跑完
要记录的指标 loss / rewards（chosen、rejected、margins、accuracies）/ logps（chosen、rejected）/ entropy / grad_norm TRL 每 logging_steps 步自动打印

跑通 1000 条之后，如果要更可信的基线，把 train[:1000] 改成 train[:10000] 或全量重跑一次即可，脚本其余不动。

四、结果怎么样：真实训练日志整理

4.1 训练概况（2026-11-07 实测）

  • 数据：UltraFeedback 1000 条 → 800 训练 / 200 验证；1 epoch；94 步；238 秒跑完；
  • 硬件：RTX A6000（48GB）单卡，bf16；训练吞吐 3.15 samples/s；
  • 产物：./dpo_output/final（最终模型）+ 完整 train.log。

4.3 每个指标怎么读

指标 含义 健康走向
loss DPO 损失 起点 ≈ 0.69（= ln 2 的”随机猜”基线；BNRM 训练时 0.7 左右的起点就是它），应持续下降到 0.5 以下（理想 0.4 上下）
rewards/margins β·log 比值差的 chosen − rejected 从 ≈0 变为正且稳定增大（论文最核心的指标）
rewards/accuracies 模型判 chosen > rejected 的比例 起点 50%，应明显上升（目标 70% 以上）
logps/chosen logps/rejected 模型给两个回答的对数似然 绝对值不能直接比（长度不同），看归一化后的 rewards/*
grad_norm 梯度范数（裁剪前） 正常应是个位数到几十，140~230 异常偏高
entropy 生成分布的熵 稳定在 1 左右说明模型没崩（实测 0.85→0.97 微升）

4.4 结论：链路跑通 ✅，偏好信号偏弱 ⚠️

好的方面（流程验证成功）：

  • 数据下载 → 分词 → 训练 → eval → 保存模型，全链路无报错，模型已存 ./dpo_output/final；
  • rewards/margins 从 0.011 一路爬到 0.126，方向完全正确（chosen 越来越压过 rejected）；
  • rewards/accuracies 从 40% 爬到 65.2%，超过了 50% 的随机线；
  • 模型没被打坏：mean_token_accuracy 稳定在 0.64、entropy 稳定在 1 左右。

不足的方面（要如实汇报）：

  1. loss 只从 0.689 降到 0.648，离 ln 2 = 0.693 的”没学”基线只低了 0.04，远没到 0.4 上下；
  2. accuracy 65.2% 只比抛硬币高 15 个百分点，还谈不上稳定分辨好坏；
  3. grad_norm 全程 140~230，远高于健康水平，说明梯度一直在被 max_grad_norm 暴力裁剪。

三个现象最可能的三个原因（按嫌疑排序）：

  1. 数据量太小：800 条训练数据对 DPO 来说太少（通常需要几千到几万条），且只训了 1 个 epoch；
  2. 学习率偏低：1e-6 且一路衰减到 5e-8，学习力度不够；
  3. grad_norm 异常：需在扩容重跑时重点观察——若仍 150+，优先排查数据格式（prompt/chosen/rejected 三字段）和 reference model 与 policy 的一致性（同一 SFT checkpoint、同为 bf16）。

4.5 汇报给老师的清单

  • 上面的三组指标表 + 4.4 的”链路 ✅ / 信号 ⚠️”判断；
  • 完整 train.log 原件；
  • 训练总时长（238s）、GPU 型号（A6000 48GB）、最终 checkpoint 路径（./dpo_output/final）；
  • 建议的重跑配置：数据 train[:1000] → train[:10000] 或全量、lr 5e-6、2~3 个 epoch，其余不变，然后对比 grad_norm 是否回落、accuracy 是否过 70%。

这是”验证训练流程”的小规模实验，不是论文级完整复现（聊天记录里 GPT 也强调了）。它的价值在于：老师后续换贝叶斯 Loss 时，模型、数据、配置、指标全部复用今天这套，新 Loss 的曲线直接和上面的基线表对比。
