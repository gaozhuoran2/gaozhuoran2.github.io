IPO vs DPO 第一轮对照实验结果分析：DPO复现成功，IPO未学习（loss卡25）与修复方案

发表于2026-11-12|更新于2026-11-11|论文学习
|总字数:1.7k|阅读时长:6分钟|浏览量:

配套阅读：实验设计与运行见《新服务器环境配置与DPO-IPO运行指南》；方法讲解见《agent对DPO论文的理解——读·跑·读三拍》与《agent对IPO论文的理解——工程视角》。

实验配置：Qwen3-0.6B 全参微调，trl-lib/ultrafeedback_binarized train[:1000]（800 训练/200 验证），β=0.1，lr=1e-6，有效 batch=8，max_length=512，1 epoch（94 步），bf16 + 梯度检查点。DPO 跑 GPU 0、IPO 跑 GPU 1 并行。结果文件：C:\Users\Lenovo\Desktop\论文学习\复现论文\IPO-DPO结果\{dpo.log, ipo.log}。

一、结论先行

DPO（GPU 0） IPO（GPU 1）
状态 ✅ 成功复现 ❌ 完全没学
loss 0.69 → 0.649（eval） 25.01 → 25（原封不动）
eval accuracy 70.1% 58.7%（≈随机）
eval margin 0.123 0.039
诊断 与旧服务器基线一致 loss 卡起点 = 好/坏回答没拉开；梯度被裁剪杀死

二、DPO：复现成功 + 一个有趣发现

与旧服务器基线逐项对照：

指标 旧服务器（A6000） 新服务器（3090） 结论
最终 eval loss 0.6479 0.649 几乎一致 ✅
eval margin 0.1263 0.1229 几乎一致 ✅
eval accuracy 65.2% 70.1% 略高（seed/版本噪声内）
训练时长 238 秒 384 秒 同量级

换卡、换机、换 TRL 版本后三个数全部对得上——基线可复现，这正是给贝叶斯 DPO 当对照组该有的可信度。

有趣发现：margin 上涨几乎全部来自”抬 chosen”——rewards/chosen 0.013 → 0.16 持续上涨，rewards/rejected 基本平（0.008 → 0.038）。这与”DPO 压坏比抬好快”的理论（Limitations of DPO，arXiv 2404.04626）相反。解释：94 步 + lr 1e-6 是极短训练，模型处于”先抬好回答”的早期阶段，该理论描述的是更长训练下的动力学。这个对照本身就是汇报素材——它标定了当前训练动态所处的阶段。

三、IPO：没学，根因找到

证据链：

  1. loss 卡死：起点 25.01（= ，π_θ=π_ref 时 h=0），终点 train_loss 25.0、eval_loss 24.93。loss 不动 = h 不动 = 模型没把 chosen/rejected 拉开。
  2. margin 没拉开：始终 0.02–0.04（DPO 同期已到 0.12）。
  3. accuracy 无提升：58.7%（随机水平）。
  4. 决定性证据：grad_norm 巨大——IPO 的梯度范数 553–1576，DPO 只有 140–230（约 10 倍）。TRL 默认 max_grad_norm=1.0 把梯度裁剪到 1，等于每步只采用计算方向的 1/500–1/1500，94 步下来模型几乎原地不动。

根因：IPO 平方损失的梯度带常数因子 （起点处），它作用在每一个 token 上；UltraFeedback 回答很长（每条几百 token），梯度被放大成巨范数，随后被裁剪杀掉。对比 DPO：sigmoid 损失数值小（≈0.7）+ σ 权重调制，梯度天然小、裁不到。本质：DPO 的 β=0.1 不能照搬给 IPO。IPO 论文的玩具实验是”3 动作、无序列长度”设定，不存在这个尺度问题——恰好印证论文没做 LM 实验留下的空白。

四、下一轮修复方案（按优先级）

  1. 调大 τ（β）：β=0.5（目标 1.0）或 β=1.0（目标 0.5）→ 梯度常数从 −10 降到 −2/−1，范数降一个量级，裁剪不再致命；
  2. 放宽 max_grad_norm：设 10.0；
  3. 拉长训练：配合 10k/全量数据（IPO 收敛慢是文献共识）；
  4. 治本预告：下一篇 SimPO 的”长度归一化 margin”正是这个病的正规解药——本次失败数据是理解它动机的最好铺垫。

五、这次失败的价值（读-跑-读第三拍的产出）

“IPO 的 τ 在 LM 尺度不能照搬 DPO 的 β=0.1”——这是一个实测发现，写进汇报比抄论文结论值钱得多。论文只给了 bandit 证据，你补上了 LM 尺度的第一块拼图（虽然是负结果，但带根因的负结果就是成果）。

六、第二轮结果（2026-11-12 更新）：裁剪修复生效，但模型学了”歪路”

修复（放宽裁剪）后的 IPO 重跑结果：

指标 第一轮（卡死） 第二轮 判定
loss 25 不动 25 → 0.25 ✅ 模型能动了
grad_norm 553–1576 30–265 ✅ 恢复正常
margin（eval） ≈0.02 0.38–0.46 ⚠️ 转正但方式可疑
accuracy（eval） 58.7% 59.2% ❌ 无提升（DPO=70%）
rewards/chosen −0.77 −5.93 ❌ 急剧转负
rewards/rejected −0.79 −6.39 ❌ 急剧转负

诊断：loss 小了 ≠ 学好了。 两个 eval 奖励双双大幅转负 = 模型给 chosen 和 rejected 的概率都比参考模型低——它没有”抬高好回答”，而是把两个回答的概率一起压下去、坏的多压一点，用退化方式凑出正 margin。原理：IPO 平方损失只约束”差”（h 离目标多远），不约束”水平”；DPO 的 sigmoid 饱和让”差够了”之后梯度自动消失，所以 DPO 的 margin 主要来自抬 chosen（+0.16），IPO 则滑向”压 everything”。800 条小样本 × 94 步下，整体压概率是满足 margin 目标最便宜的方向——小样本漂移解是第一嫌疑。

下一轮：① 确认当前脚本的 beta / max_grad_norm 值；② 方案 A（主推）：数据升 10k + β=0.5 + max_grad_norm=10，通过标准改为 accuracy > 65% 且 rewards/chosen 回正（不再看 loss）；③ 备选：β=2.0 更保守目标（0.25）。

附注：日志中 HTTP Error 429 为 hf-mirror 限流警告，无害。

七、当前状态与待办（2026-11-12 记录，暂停点）

决策：大数据（10k / 全量）暂缓，等之后有时间再跑。当前进度冻结在”1000 条小样本”档。

已完成的（可引用）：

实验 状态 关键结果
DPO @ 1000 条 ✅ 完成 eval loss 0.649 / accuracy 70.1% / margin 0.123，复现旧基线成功
IPO @ 1000 条 第一轮 ❌ 卡死 loss 卡 25：grad_norm 553–1576 被默认 max_grad_norm=1.0 裁剪杀死
IPO @ 1000 条 第二轮 ⚠️ 能动但退化 loss 0.25、accuracy 59.2%、chosen/rejected 奖励双双转负（漂移解）

恢复实验时按此待办清单执行：

  1. 确认配置：查看 train_ipo.py 里当前的 beta 与 max_grad_norm 具体值（第二轮用了多少要记录在案）；
  2. 方案 A（主推）：数据升 train[:10000] + beta=0.5 + max_grad_norm=10.0，双卡并行跑 DPO/IPO——通过标准：accuracy > 65% 且 rewards/chosen 回正（不再看 loss）；
  3. 方案 B（备选）：若 A 仍漂移，试 beta=2.0（目标 0.25，更保守）；
  4. 最终基线：通过后跑全量 62.6k × 1 epoch（约 5.4 小时/方法，双卡并行），对标 Zephyr 规模；
  5. 每一步把新日志发 agent 做对照分析。

恢复所需上下文（文章链接）：运行手册《新服务器环境配置与DPO-IPO运行指南》（环境 rl、目录 ~/rl/ipo、脚本与超参均在文中）；IPO 日志解读见《agent对IPO论文的理解——工程视角》第 5 节。
