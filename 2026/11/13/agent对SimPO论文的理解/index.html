阅读方式：沿用”先工程后数学”——第 0–6 节只讲工程（改了什么、怎么跑、看什么日志），第 7–8 节讲数学。这篇对你特别重要：它的长度归一化 + 小 margin，正好是你 IPO 漂移实验的解药。

0. 一句话先讲清楚 SimPO 是什么

SimPO 对 DPO 改了两处、删了一处：

① 奖励换成”序列平均对数概率”（÷ 回答长度，长度归一化）→ 删掉参考模型；
② BT 目标里减一个目标 margin γ（要求胜负奖励差至少 γ，而不是只要求为正）。

你之前跑 DPO/IPO 的一切机器（输入三元组、policy 前向、log-prob 收集）全部复用，只是：模型从 2 个变 1 个（ref 没了）、前向从 4 次变 2 次、损失公式换一行。

1. 工程清单：DPO / IPO / SimPO 三兄弟对比

输入 (x, y_w, y_l) 同左 同左 ✅
模型数 2（π_θ + 冻结 π_ref） 2 1（只有 π_θ） ✅
前向次数/步 4 次 4 次 2 次（θ × chosen/rejected）
显存 13–15GB（0.6B） 同左 约减半（无 ref、无 ref 前向）
损失 −logσ(β·logratio差) (h − 1/2τ)² −logσ(β·平均logp差 − γ)
超参 β=0.1 τ（=β） β∈[2.0,2.5] + γ∈[0.5,1.5]

4. 超参：尺度和 DPO 完全不同（容易踩）

参数 论文推荐 为什么这个尺度
β 2.0–2.5 平均 logp 量级很小（≈ −1/token 附近），需要大 β 把奖励差放大；DPO 的 β=0.1 是对”log-ratio 差”的尺度，不能照搬
γ 0.5–1.5 目标 margin。太小=没约束，太大=模型退化（见第 7 节——你的 IPO 漂移就是”太大”那一侧）

loss 起点提醒：初始 π_θ = SFT 时平均 logp 差 ≈ 0 → loss ≈ −logσ(−γ) ≈ 1.31（γ=1.0）。所以 SimPO 的 loss 起点 ≈ 1.3——既不是 DPO 的 0.69 也不是 IPO 的 25。跨方法照旧只比 accuracy/margin，不比 loss。

5. 你的实验方案（最小改动 + 一个意外福利）

  1. 脚本：train_dpo.py 复制成 train_simpo.py，按第 3 节改三处（loss_type / beta / gamma）——其余全部不动；
  2. 运行：双卡并行——卡 0 跑 DPO 基线、卡 1 跑 SimPO（CUDA_VISIBLE_DEVICES 各设各的）；
  3. 意外福利：SimPO 没有 ref 模型，显存从 ~14GB 降到 ~8GB——卡上还有富余，之后跑 10k/全量数据时可以把 per_device_train_batch_size 提到 2 甚至 4，速度翻倍；
  4. 看日志的口径（沿用 IPO 的教训，不看 loss）：
    • rewards/chosen 与 rewards/rejected 分开看——SimPO 应该”抬 chosen”（chosen 回正、朝 +0.5 以上走），如果像 IPO 那样双双转负就是又漂移了；
    • rewards/accuracies 对标 DPO 基线（70.1%）；
    • margin 的口径变了（长度归一化 + γ 平移），不要和 DPO 的 0.123 直接比大小。

6. 两个组件的消融证据（论文表 5，Mistral-Base）

配置 AlpacaEval 2 LC (%) Arena-Hard WR (%) 说明
DPO 15.1 10.4 基线
SimPO 21.5 16.6 完整版

SimPO γ=0（去掉 margin） 16.8 11.7 明显下降 → margin 也重要，但不如 LN 关键

两个组件的分工：LN 防”长度作弊”（没有 LN 时模型发现”把回答写长 = 概率求和更高”的捷径，生成又长又重复）；γ 防”躺平”（没有 γ 时模型只把奖励差做到刚刚为正就停，不追求更清晰的分离）。

7. 和你 IPO 漂移实验的直接呼应（这篇对你最重要的一节）

你 IPO 第二轮的病：loss 0.25 但 accuracy 59%、chosen/rejected 奖励双双转负——模型靠”把两个回答的概率一起压低”凑 margin。SimPO 论文的图 3c 就是这个病的官方诊断书：

随目标 margin γ 增大，学到的胜出回答平均对数似然整体下降，分布被拉平——“起初改善性能，最终导致模型退化”。

翻译成你的实验语言：margin 目标设得太大时，模型发现”压低 winning 的概率”比”抬高 winning”更省力，于是滑向退化解。 你的 IPO β=0.1 → 目标 ，作用在未归一化的 log-ratio 差上——按 SimPO 的尺度换算，这是一个”巨大”的 margin，正好落在图 3c 的退化区。

SimPO 开出的药方恰好是对症的：①先长度归一化（把 margin 目标放到合理尺度上）；②margin 设小（γ 最优 0.5–1.5，对应归一化后的尺度）。你下一轮 SimPO 实验如果 chosen 奖励回正、accuracy 超过 DPO 的 70.1%，就同时验证了”IPO 漂移 = margin 尺度病”这个判断——一条证据链串起两篇论文，汇报里非常值钱。

8. 数学部分：三个”为什么” + 一个”病灶”

8.1 为什么用平均 logp（长度偏差的机理）

用 token 对数概率之和当奖励时， 天然随长度变负——500 个 token 的和 ≈ 500 × (−1) = −500，100 个 token 的只有 −100。于是”长回答”天然低奖励，模型被迫给长序列”注水”（抬每个 token 的概率）才能让 赢过更短的 ——这就是长度作弊。除以 之后，奖励变成”每个 token 平均有多大概率”，与长度无关，且恰好是 beam search / 多选题里常用的排序度量——训练奖励与生成度量从此一致。

8.2 为什么 margin γ 有效（SVM 的直觉）

式 5 里 的作用等于 SVM 的 margin：不只要求 ，还要求差至少 γ。直觉上，margin 越大，分类边界离两类样本越远，泛化越好（图 3a 证实：γ 越大，留出集奖励准确率越高）。但边际递减且会反转（图 3a 的 ∩ 形曲线）：γ 太大时模型开始压 winning 的概率来凑差距（8.3 的病灶）——这就是为什么 γ 要待在 [0.5, 1.5] 的甜蜜区。

8.3 病灶解剖：为什么 margin 太大 = 你的 IPO 漂移

平方损失或大 margin 都只约束”差“，不约束”水平“。当目标差距超出模型”合理抬高 winning”能达到的范围时，最便宜的满足方式是把两边一起压低、坏的压多一点： 达标了，但两个概率都崩了。图 3c 的”winning 平均 logp 随 γ 增大而下降”、你 IPO 的”chosen/rejected 奖励双双转负”是同一个病的两个病例。

8.4 为什么没 KL 也不遗忘（三个护身符）

SimPO 删掉 ref 模型，等于删掉了显式 KL 正则。论文的答案：①小学习率（1e-6，慢改参数）；②偏好数据覆盖多样领域（不会只朝一个方向漂）；③LLM 本身鲁棒。实测 KL(π_θ‖π_ref) 训练后仍很低。工程含义：lr 别乱调大，数据别太窄——这两条你现在的配置都满足。

8.5 DPO 的”50% 错位”病灶（SimPO 的出发点）

DPO 训练目标优化的是”相对 ref 的概率比排序”，但推理生成时用的是”绝对似然排序”——两者不是一回事。论文实测：DPO 训练后，训练集中只有 ~50% 的三元组满足 （平均似然口径）——等于没学到排序。梯度分析（附录 F，式 7）给出机理：DPO 的梯度按”求和 logp”计算、无长度归一化 → 长序列获得更大梯度、主导训练。SimPO 把奖励直接换成平均 logp，从源头对齐。

9. 与你研究的衔接 + 全文一张表收尾

  1. 三兄弟的定位：DPO = 带参考的对数比（隐式 LN）；IPO = 带参考的平方回归（理论正则化）；SimPO = 免参考 + 显式 LN + 小 margin（工程最优）。你跑齐三兄弟后，”参考模型、长度归一化、margin 形式”三个变量的贡献就全部分离了——这正是给贝叶斯 DPO 选”该在哪加不确定性”打的地基。
  2. 贝叶斯 DPO 的接口：SimPO 的 γ 是确定性 margin；贝叶斯版可以让 margin 带上不确定性（回到 MAVRL/MF-BNRM 的”随机变量进 σ”套路），或者给”平均 logp 奖励”配一个后验分布。SimPO 因为结构最简（一个模型、一个奖励），是最容易做贝叶斯化的底座。
  3. 你手上 800 条实验的直接意义：SimPO 跑通后，你就有 DPO/IPO/SimPO 三组同数据基线——三组对照本身就是一篇像样的复现报告。
